# Pending Tests

The current release needs manual verification in these areas:

- Canvas overlays while zooming: node prompt panels and the node/connection create menus should keep a constant on-screen size at any zoom level, and the "Select references" hint button should stay centered at the top of the viewport instead of drifting with the canvas.
- Reference selection mode: entering it should hide the node hover toolbar, tint the canvas with an accent ring, switch the canvas cursor to a crosshair, and show an accent-colored hint at the top saying references can be picked on the canvas or in the left element list; ESC should return to the input.
- Create menus: the node menu on double-clicking empty canvas and the connection create menu should render tighter (smaller items, icons, text), and node names in the double-click menu should follow the app language.
- Duplicate / copy-paste: duplicating a node (or pasting copied nodes) should carry the inbound reference connections over to the new nodes, while outbound connections stay untouched.
- Regenerate behavior: the default preference should preserve the original behavior (generating on a node that already has content creates a new node). Switching the preference to "overwrite" should replace that node in place (no new node, no new connection, and image nodes should no longer use their own image as a reference). Config nodes should always create a new result node. Generating in place must keep the node's current size — including a node whose size happens to equal the default (for example a duplicated node) and an empty node the user resized beforehand — instead of snapping it to the generated image's fitted size.
- Generation snapshot reset: a generated node records the parameters, prompt and reference nodes it was generated with. On an image node with content, the prompt panel should show a reset button that is disabled until the model/settings, the prompt or the references differ from that snapshot, then restores all three (including disconnecting/adding reference connections). Uploaded images have no snapshot and must not show the button, and "copy the prompt that generated this image" and retry must use the same snapshot values.
- Generation parameter memory: changing the model, resolution, ratio, count, quality, video or audio parameters in a generation config should be remembered per canvas and per mode (image/text/video/audio), so the next new generation config opens with those values instead of the defaults. Switching the mode inside a config should refill that mode's remembered values (falling back to the preference defaults when there is no memory yet). The memory must travel with the canvas on export/import, and a canvas without memory (or an older imported canvas) must fall back to the preference values. Prompts, composer content and references must never be remembered.
- Locked while generating (visuals): while a generation runs the disabled controls must also *look* disabled — the reference bar's add button, the prompt box (dimmed text plus an inset border), the model picker, the settings pills, the prompt library, the expand button and the reset button (whose icon turns grey when reset is unavailable). The node hover toolbar must additionally disable the actions that would change the node's content — replace/upload, mask edit, crop, split, upscale, AI super-resolve, angle, reverse prompt and delete — shown at about 35% opacity with a not-allowed cursor. Clicking a reference item or a prompt chip must still focus that node and keep the hand cursor.
- Locked while generating: while a generation runs, the node's reference add/remove, prompt and composer editing, generation mode, model picker and every generation settings control must be disabled, and an already-open settings popover must close. The primary button must still work as Stop, and focusing a reference by clicking a chip may stay available.
- Error log: the canvas top bar has a log icon that shows a red dot once something has been logged. It must record every error the app reports (an antd `message.error` from any page, a generation failure with the provider's full error text, and uncaught errors or promise rejections), newest first, with the time and the full selectable text, and offer "Copy all" and "Clear"; entries last for the session. Generation failures must no longer vanish on their own — they show a top-right notification that stays until it is dismissed.
- New defaults: a fresh install (or a browser whose app storage was cleared) should start with the canvas image count at 1, "when a node already has content" set to overwrite in place, and auto-center on select enabled. These are defaults only — an existing browser keeps the values it already saved, so to check them either toggle the setting in Preferences or clear the app's stored config.
- Uploaded material with in-place generation: with the "already has content" preference set to overwrite, generation entry points (copy/reverse prompt, a text node's generate action, and the bottom generation panel) are hidden only for nodes whose content the user provided — uploaded or dropped files, pasted images/text, content inserted from "my assets", or text typed into a text node. Nodes the app generated, and every node that predates this change (including images generated before generation snapshots existed), must open the generation panel normally again. Switching the preference back to creating a derived node restores everything.
- Channel editor cancel: clicking "Add channel" and then cancelling (or closing the drawer) must not leave a channel behind — the new channel should only appear in the channel list after saving. Editing an existing channel and cancelling must keep it unchanged.
- Provider presets: the channel editor should offer a service-provider list (Custom / OpenAI / Gemini / HeyRoute / Infistar / PackyCode). Picking a built-in provider must fill the channel name, the protocol and the API endpoint and lock those three fields (the API key and the model list stay editable); picking Custom must unlock them and keep whatever values are currently filled. Saving and reopening the channel must keep the values. Base URLs are stored without the version segment (the app appends `/v1` itself, and call-script templates append it too), so Infistar (`https://infistar.cc`) and PackyCode (`https://www.packyapi.ai`) are OpenAI-protocol presets where adding a `gpt-image-2` model and an API key is enough to generate images.
- HeyRoute protocol (needs a real key to verify): a channel using the HeyRoute preset (`https://heyroute.ai`, requests go to `…/v1/images/generations`) must generate and edit images. The app now reads the response as an SSE stream and takes `data[0].b64_json` from the `completed` event — before this change HeyRoute's stream came back as content the app could not parse. Video must create a task on `/videos`, poll roughly every 15 seconds and download the finished file from `/videos/{id}/content`. Worth checking while testing: multiple reference images are sent as repeated `image` fields on `/v1/images/edits`, a model with a fixed duration may reject the configured seconds value, and images are sent with `response_format: b64_json` (no remote URL fetch, so no CORS issues). Text generation is deliberately not covered: the app calls the OpenAI Responses API, which HeyRoute only offers for some models, so a HeyRoute text model may still fail.
- Tooltip theme (app-wide): every hover tooltip in the app should share one themed popup — canvas panel surface, border, text color, no arrow, same enter delay. This covers the canvas bottom toolbar, node hover toolbar, nodes, tool/dialog buttons, the element list, the zoom dock, the top bar, the top navigation, the Agent panel, the image workbench, settings and the plugin manager, and must look correct in both light and dark mode. Two previous sources of a second style are gone: the bottom toolbar's hand-rolled tip and the native browser `title` attributes on list rows and icon buttons. The multi-selection floating toolbar itself must also follow the canvas theme instead of staying white in dark mode. Note that a disabled button shows no tooltip (the browser sends it no pointer events), which is expected.
- Element tooltips follow the cursor: in the element list, hovering a node row or a thumbnail tile should show its tooltip just below-right of the pointer and keep it moving smoothly with the pointer instead of sitting on the row and covering the neighbouring row's text. Moving fast should stay smooth, and the row's own hover preview plus click / multi-select / reference-pick behaviour must keep working.
- Enter no longer generates: in the generation prompt panel, pressing Enter must insert a newline instead of starting a generation, and the newline must survive (reopening the panel keeps the line breaks); generation must only start from the primary button. When the `@` mention menu is open, Enter must still pick the highlighted candidate.
- Canvas elements view: the header toggle switches the element list between list and a thumbnail grid, and the choice persists across reloads. In grid mode, image nodes show previews and other node types show their icon without a background.
- Element hover preview: hovering an image or video node in the element list shows a left-aligned preview over the canvas (fixed gap on the left) at about the focused-node size, styled like the image detail view (dimmed canvas behind a titled panel) so it is not mistaken for a canvas node. It must stay pointer-events-none so the list keeps working, moving between rows should update the preview, and a large image must not overflow the canvas area.
- Toolbar focus: the first group of the bottom toolbar has a "center focus" button that centers the currently selected node, the same as clicking it in the element list. It is disabled when nothing is selected.
- Auto-center on select: with the new preference enabled, clicking a node on the canvas (opening its generation config) should center it; with it off (default) the behavior is unchanged.
- Reference selection from the element list: while in reference-selection mode, clicking a node in the side panel list adds it as a reference instead of centering it; clicking an already-added node removes that reference (hover reads "Remove reference"), while already-added nodes stay dimmed. Nodes that cannot be used are dimmed and not clickable.
- Focus history and reference jumps: hovering a reference chip in the prompt shows a thumbnail preview, and clicking a "Reference content" entry or a chip focuses that node. The bottom-toolbar back/forward buttons move through focus history (every focus trigger is recorded), skip deleted nodes and consecutive repeats, and the limit is configurable in Preferences. In Preferences the scrollbar is hidden and a fading down-chevron shows at the bottom while more content can be scrolled; the focus history limit field sits above auto-center and renders as a single row. Focusing through any entry point (canvas click with auto-center on, the toolbar center button, the element list, back/forward, or a reference) should open the target node's panel first, show its hover toolbar, and land the node in the same place. This must hold for the reference-bar and prompt-chip jumps too, even after the window or canvas has been resized: those must use the current canvas size, not a stale one, so the node and its panel are never squeezed into the top half. `F` should center the selected node, and `[` / `]` should move back and forward through focus history; both are listed in the shortcuts modal and do nothing while typing in a field.
- Shortcuts modal: the one opened from the canvas top bar and the one from the zoom dock should show the same grouped list (View / Selection & editing / Focus / Media) with uniform `kbd` keycaps, and every row and keycap must stay legible in both light and dark themes, with nothing clipped in Chinese or English (long English labels and key clusters wrap onto a second line instead). Redo should appear once with `Ctrl / Cmd + Shift + Z` and `Ctrl / Cmd + Y` as the alternative.
- Resource hover previews: hovering an image/video item in the node reference bar and hovering a reference chip in the prompt should show the same preview panel (one shared component), about twice the previous size, hugging the media with no letterbox bars, and using the canvas panel surface in both themes. Text and audio references should still preview through the same panel. Moving the pointer off the item (including onto the preview itself) must hide it immediately in both places, and a preview with no room above should flip below the item.
- Image decode during focus jumps: canvas node images, reference thumbnails, element-list thumbnails and prompt thumbnails should decode asynchronously, so focusing or panning to an image-heavy area no longer stutters. Thumbnails should not lazy-load: every thumbnail in a mounted list must decode off the main thread instead of waiting for the raster step, and if any list shows blank or late thumbnails, note which list.

- Desktop shell: building `desktop/` with `bun run build` (Tauri) should produce a single self-contained `infinite-canvas.exe` that opens the home page on double click, without starting any local port. Canvas CRUD, image/video generation via the user's own API, asset downloads, and plugin loading should match the `localhost:3000` web experience. The desktop build must not render the Agent icon in the canvas top bar or the top navigation, must not auto-open the Agent panel when opening a project, and must not auto-connect to a saved Agent token. The web build (`bun run build`) must keep all Agent entry points unchanged.

- Canvas image previews: canvas image nodes, the left element list, the node reference bar, my-assets cards, the asset picker, image workbench result cards and history thumbnails, and the image/video workbench reference strips all render from a preview capped at a 768px long edge, so image-heavy views no longer decode the originals. Opening the full-size image, editing, downloading, exporting, and generation references must keep using the original; an image that is already at or under 768px, exists only as a remote URL, or uses a custom cover should fall back to the original.

When zoomed or panned so only part of the canvas is visible, every connection crossing the viewport should still render (including ones whose endpoints are both off-screen), connection click selection and the context menu should still work, and the dashed preview while creating a connection should follow the cursor as before.

After a page refresh, a still-pending video should keep polling automatically; if polling stopped, **Get task status** should resume with that task ID until the video is ready, the task fails, or the status request errors. Task failure should then allow a normal retry that creates a new generation.

## 图片分辨率尺寸表

选择分辨率和宽高比后，W/H 按下表填写，单位为像素。预设尺寸不受「16 倍数对齐」开关影响；该开关只控制手动输入尺寸时的对齐。最终生成尺寸以所选模型的实际输出为准。

| 宽高比 | 1K | 2K | 4K |
| --- | ---: | ---: | ---: |
| **1:1** | **1024 × 1024** | **2048 × 2048** | **2880 × 2880** |
| **2:3** | 1024 × 1536 | 1360 × 2048 | 2336 × 3520 |
| **3:2** | 1536 × 1024 | 2048 × 1360 | 3520 × 2336 |
| **4:3** | 1024 × 768 | 2048 × 1536 | 3312 × 2480 |
| **3:4** | 768 × 1024 | 1536 × 2048 | 2480 × 3312 |
| **16:9** | 1536 × 864 | 2048 × 1152 | **3840 × 2160** |
| **9:16** | 864 × 1536 | 1152 × 2048 | **2160 × 3840** |
| **21:9** | 2016 × 864 | 2688 × 1152 | **3840 × 1648** |
| **9:21** | 864 × 2016 | 1152 × 2688 | **1648 × 3840** |
